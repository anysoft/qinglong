- Async operation service in HTTP Backend process: acquire cross-process provider EX flock first, then validate state and transaction-create QUEUED operation with owner UUID; hold Node FileHandle for entire promise. Small Python helper flocks inherited FD3 then exits (same open file description keeps lock in Node). No memory-only mutex.
- Operation command runner reuses observeChildProcess and existing shell/hook_process.py (generic POSIX supervisor using process_group.py) with inherited lease FD3; build descendants hold lease. Backend EOF causes supervisor kill/reap before lock release. Separate Runtime service, no TaskHookLifecycle or Config/B17 locks touched. Runtime cancel API accepts only operation ID, marks cancel_requested DB flag; owner polls and signals its actual held ChildProcess object, never trusts raw stored PID. Other Backend process can request cancellation through DB.
