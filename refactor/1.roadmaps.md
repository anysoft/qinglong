# Greenfield Platform Roadmap（Phase 4.5A 提案）

当前方向仅 Fresh Install，不支持 QingLong migration/compatibility。Phase 0–4 的实际交付保留为历史记录；以下未完成项只是计划，不表示已授权执行或已实现。

| Phase | 模块 | 状态 | 目标与边界 |
| --- | --- | --- | --- |
| 0 | Architecture Audit | 完成/历史 | 原架构与测试证据，兼容契约已被新方向取代 |
| 1 | GitCredential + Repository | 完成 | 独立身份/凭据核心保留，兼容adapter待4.5B清理 |
| 2 | Persistent Git + Worktree + Lock/Lease | 完成 | 保留数据安全与生命周期 |
| 3 | Managed Subscription Pipeline | 完成 | 去双轨后成为唯一Sync；scripts/discovery仍为桥 |
| 4 | Scoped ENV | 完成 | Profile/Task overlay已实现；Global完整统一待4.5B |
| 4.5A | Greenfield Audit | 完成 | 清单、依赖、风险、删除计划；生产代码不改 |
| 4.5B | Cleanup / Consolidation | 待正式执行任务 | fresh operational schema、Repository-only、旧Git清理、有限ENV整合、API/UI收敛；保留桥 |
| 5 | Config Assets + Hooks v2 | 计划 | 独立配置资源及before/success/failure/finally |
| 6 | Python Runtime | 计划 | 可选择的managed executable，与系统Python分离 |
| 7 | Python Environment | 计划 | venv/依赖/锁/缓存与可复用环境 |
| 8 | Node Runtime + Environment | 计划 | 版本、项目依赖、显式解析及安装隔离 |
| 9 | Task Domain | 计划 | Task/Schedule/source binding与用户覆盖 |
| 10 | Execution Engine | 计划 | immutable context/Runner/lease/exit/log/result IPC；替换调度执行桥 |
| 11 | Discovery / Trigger | 计划 | DiscoveryPolicy→definitions→reconcile；不执行源码发现 |
| 12 | Editor | 计划 | Worktree文件编辑；最后scripts消费者退场 |
| 13 | Notification / Observability | 计划 | TaskRun/SyncRun identity、领域事件、指标与通知 |
| 14 | Backup / Final Consolidation | 计划 | 新平台资源与唯一Git数据备份，最终清桥；不做QingLong migration |

具体顺序和gate见[4.5B执行顺序](../docs/refactor/phase4.5/10-cleanup-execution-order.md)。阶段编号不覆盖依赖：scripts只能在Task/Runner/Discovery/Editor全部退出后删；preload只有在ENV/hooks/runtime/SDK责任都有接替后整删。
